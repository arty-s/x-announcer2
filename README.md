# X-Announcer 2

Объявления бортпроводников для X-Plane 12 — вторая версия, нативный плагин на
C++ и XPLM SDK. Ветка 1.x (`D:\claude2\x-announcer\`, FlyWithLua, v1.1.4) остаётся
в проде и служит источником доменной логики; сюда она переносится по частям.

Почему ушли с FlyWithLua: один растровый шрифт без кириллицы, отсутствие TLS,
недостижимая прозрачность окна ImGui и недокументированное подмножество
биндингов imgui. Все четыре стены в нативном плагине исчезают.

## Состояние

Ядро (машина фаз, очередь объявлений, две шкалы времени) перенесено из 1.x и
**сверено с ней трасса-в-трассу на десяти сценариях из двенадцати** (два
расхождения названы вслух, см. `v2only`). Звук играет, авиакомпания определяется
по ливрее (сверено на 155 ливреях диска), настройки живут в `config.ini` и
правятся во вкладке «Настройки», варианты файлов внутри пака выбираются по тегам,
интерфейс оформлен. Не перенесены: SimBrief и виджет фазы.

## Настройки

Файл `config.ini` лежит рядом с плагином, пишется при первом запуске, каждый
ключ снабжён комментарием по-русски. Правки в панели применяются сразу, а файл
перезаписывается через пару секунд после последней правки — и при выгрузке
плагина, чтобы выход из симулятора не съел изменение.

Ключи — те же, что в 1.x, с двумя осознанными отличиями: `music_bus` по
умолчанию `interior` (шины XPLM зовутся иначе, чем микшер FlyWithLua, и `master`
среди них нет; музыка при посадке пассажиров звучит в салоне, там же, где и
экипаж), а пустой `library` означает папку **`Sound_packs` рядом с
плагином** — она создаётся при первом запуске, и туда кладут по папке на
авиакомпанию. Свой путь можно вписать в поле «Папка со звуками».

Один ключ добавлен: `default_fallback`. Если у авиакомпании нет какого-то
объявления, оно берётся из набора `Default` — так делает и 1.x, и по умолчанию
так же делает v2. Выключите, если предпочитаете тишину в этих местах одному
голосу за другим; в таблице на вкладке «Библиотека» видно, какие объявления от
этого замолчат.

Два ключа 1.x удалены. `auto_find` искал `D:\UA_Sounds` и ещё пару дисков, то
есть зашивал имя папки одного человека в чужие установки. `music_max_loops`
ограничивал число повторов фонового трека — в 1.x это держало утечку памяти
FlyWithLua, а слышно было другое: музыка обрывалась посреди посадки пассажиров.
Здесь трек играет, пока идёт фаза, которая его завела. Оба ключа в старом файле
вызывают пометку в журнале и исчезают при следующей перезаписи. Ключи, которых
эта версия ещё не понимает (`simbrief_id`, `widget*`), наоборот, сохраняются.

Разбор файла жалуется в журнал построчно: непонятое значение не отбрасывает
остальной файл и не остаётся незамеченным. `enabled = True` в 1.x молча выключал
плагин целиком — здесь понимается, а `enabled = может быть` оставит прежнее
значение и скажет об этом.

Сверка дефолтов с 1.x — отдельная проверка стенда:

```powershell
python tests\diff_config_vs_1x.py
```

## Звук

`XPLMPlayPCMOnBus` принимает только PCM16, поэтому каждый файл пака — ogg, mp3
или wav — декодируется самим плагином (`stb_vorbis` + `dr_mp3` + `dr_wav`, все
public domain). **FMOD не линкуется вообще:** `XPLMSound.h` объявляет нужные
типы сам, если FMOD не подключён. Отсюда нет ни требований атрибуции, ни риска,
что наш экземпляр `fmod.dll` окажется не тем, которым владеет X-Plane.

Декодирование минуты Vorbis заметно в кадре, поэтому оно уходит в рабочий
поток; на главном потоке остаётся только передача готового буфера X-Plane —
там `XPLMPlayPCMOnBus` и обязан вызываться. Буфер живёт до колбэка завершения:
SDK прямо предупреждает, что канал исчезает сам, когда сэмпл кончился.

Длительность берётся из заголовка контейнера, без полного декодирования, и
кэшируется — её спрашивают ровно в момент старта объявления, а чтение диска в
этот момент это подтормаживание кадра. Стенд сверяет быстрый замер с полным
декодированием на реальных файлах: расхождение по всей библиотеке — 0.00 с.

## Офлайн-стенд

```powershell
build\xa_test.exe                     # сценарии + детерминизм + эталонные трассы
python tests\diff_vs_1x.py            # рейсы против ветки 1.x (нужен lupa)
python tests\diff_airlines_vs_1x.py   # детект по всем ливреям машины
python tests\diff_config_vs_1x.py     # дефолты настроек
```

Стенд делает четыре вещи на каждый сценарий:

1. **Проверяет ожидания**, записанные в самом сценарии (`expect phase`,
   `expect played`, `expect playing`).
2. **Проверяет согласие виджета с машиной**: фаза не имеет права смениться на
   следующую, пока список условий ещё показывает невыполненное. Именно это
   ловит расхождение подсказки с логикой.
3. **Проверяет детерминизм**: тот же сценарий, прогнанный дважды, обязан дать
   побайтово ту же трассу. Без этого сверка с 1.x бессмысленна.
4. **Сверяет трассу с эталоном** в `tests/golden/`.

**Сценарии — данные, а не код** (`tests/scenarios/*.scn`). Один и тот же файл
проходит и через ядро v2, и через плагин 1.x на Lua, а трассы сравниваются:
порядок событий — строго, время — с допуском 2 с (реализации обслуживают
очередь на разных долях кадра). Это единственная защита от того, что логика
уедет во время самого переноса: тест, написанный по новому коду, повторил бы
то же непонимание, а старая реализация знает, как было на самом деле.

Длительности задаются точно и без реальной библиотеки: сверялка пишет для
каждого объявления 44-байтный WAV, в заголовке которого заявлена нужная длина.
1.x читает длительность из заголовка чанка, поэтому обе стороны видят ровно то
число, которое написано в сценарии.

### Что стенд уже нашёл

**Пак без файла `DisembarkStarted` навсегда оставлял машину в `TAXI_IN`**:
переход в `DISEMBARK` происходил только если объявление реально ушло в эфир, а
сброс рейса живёт именно в `DISEMBARK` — значит второй рейс за сессию молчал
целиком. Объявление и переход разделены; исправлено сразу в обеих ветках
(1.x `e3f5578`, релиз v1.1.5; v2 `225750b`), сценарий `03-empty-library`.

**Три объявления не имели триггера НИ В ОДНОЙ ветке.** `DepartureDelayed` лежал
в таблице событий и в панели, а сыграть не мог никогда — условия для него не
существовало; `CruiseElapsed50Percent` и `CruiseElapsed75Percent` не имели даже
имени, хотя файлы для них лежат в паке Qatar. Найдено сверкой таблицы событий с
тем, что движок действительно умеет завести, а не чтением кода. Теперь задержку
отмеряет `delay_after` (посадка идёт дольше порога), а долю маршрута — расстояние
до последней точки плана FMS, замеренное один раз при отрыве. Сценарии
`11-departure-delayed` и `12-route-marks`, обе ветки совпадают трасса-в-трассу.

**Пак, который держит звуки в подпапке `Default`, молчал целиком.** Правило
«корень пака плюс одна языковая подпапка» такую папку не читает, а пак Gulf Air
устроен ровно так: в корне пусто, все 21 файл на уровень глубже. Играл при этом
глобальный `Default`, то есть пак выглядел рабочим. Теперь подпапка читается,
но **только если в корне не нашлось ничего** — иначе паки, у которых есть и то и
другое (Ryanair, 22 файла в каждом), получили бы каждое объявление дважды.

**Многоязычный пак звучал наугад.** v2 обходил пак рекурсивно и сваливал все
языковые подпапки в одну кучу — какая победит, решала файловая система. 1.x
всегда читал ровно одну: запрошенную в `language` или единственную имеющуюся.
Найдено при переносе `config.ini`, выбор вынесен в ядро
(`core/pack_layout.cpp`), где стенд его и проверяет.

В `src/core/` не входит ни строчки XPLM, FMOD, файловой системы или сети —
именно поэтому стенд гоняет целые рейсы за миллисекунды и сравнивает их с 1.x.

## Сборка

Нужны только Visual Studio Build Tools 2022 с компонентом C++ — CMake и Ninja
берутся оттуда же, ставить и прописывать в PATH ничего не надо.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

Установка в симулятор (`Resources\plugins\x_announcer2\`):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Install
```

Результат сборки — `build\x_announcer2\{win_x64\x_announcer2.xpl, assets\}`.

## Технические решения

**Звук — без FMOD.** `XPLMSound.h` объявляет собственные `FMOD_*` типы, поэтому
`XPLMPlayPCMOnBus` доступен без заголовков и библиотек FMOD. Библиотека паков —
687 `.ogg` и 13 `.mp3`, декодируем сами (`stb_vorbis` + `dr_mp3`) и отдаём PCM16
в шину `xplm_AudioInterior`. Это снимает линковку FMOD, требования атрибуции и
риск, что наш экземпляр `fmod.dll` окажется не тем, которым владеет X-Plane.
Побочная выгода: декодер и планировщик — чистый код, он тестируется на стенде.

**Рисование — фиксированный конвейер GL 1.1.** X-Plane 12 рендерит через Vulkan,
но плагинам доступен только OpenGL. Клиентские массивы GL 1.1 экспортируются
самим `opengl32.dll`, поэтому загрузчик расширений не нужен. Состояние меняется
через `XPLMSetGraphicsState`, текстуры биндятся через `XPLMBindTexture2d` —
иначе представление X-Plane о состоянии GL разъезжается с действительностью.

**Отсечение (scissor).** Прямоугольники нужны в физических пикселях, а ImGui
работает в бокселях. Масштаб не угадывается, а считается: точка прогоняется
через матрицы, которые X-Plane выставил на этот кадр. Первый кадр печатает в
`Log.txt` вьюпорт и пересчёт угла окна — если окно окажется пустым, диагноз
начинается оттуда.

**Предохранитель.** Ошибка в Lua останавливала только движок Lua; здесь она
роняет симулятор. Все точки входа обёрнуты, десять ошибок подряд выключают
плагин с явной записью в журнал.

## Проверено на машине Артёма

- Собирается: MSVC 14.44, C++17, `/MD`, без предупреждений.
- `.xpl` — 64-битная DLL, экспортирует `XPluginStart/Stop/Enable/Disable/ReceiveMessage`.
- Зависимости: `XPLM_64.dll`, `OPENGL32.dll`, системные + MSVC-рантайм (на месте).
- Установлен в `E:\SteamLibrary\...\X-Plane 12\Resources\plugins\x_announcer2`,
  хэш сверен.

**Не проверено:** живой запуск в симуляторе. До него всё остальное не имеет смысла.
